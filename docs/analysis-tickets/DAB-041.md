## Context

`ErrorManager.categorize_error` computes `error_class = type(error).__name__.lower()` and never
reads it again. Classification therefore depends entirely on the *message text*, and the exceptions
that carry their meaning in their **type** rather than their message fall through to
`UNKNOWN_ERROR`, which is not in the retryable set.

`asyncio.TimeoutError()`, `TimeoutError()`, `ConnectionError()` and `ConnectionResetError()` all
stringify to `""`. They match nothing. **The two most common transient faults in a Discord/Gemini
bot are classified as permanent.**

The variable that would fix it is already there. This is the highest payoff-per-line fix in the
whole corpus.

## Reproduction

```python
from src.utils.error_manager import ErrorManager, ErrorType
import asyncio
em = ErrorManager()
print(em.categorize_error(asyncio.TimeoutError()))      # UNKNOWN_ERROR
print(em.create_error_context(asyncio.TimeoutError()).should_retry)   # False
```

## Files to touch

- `src/utils/error_manager.py` — `:180-181` (the dead assignment), the substring chain `:170-241`,
  the retryable set `:265-276`, log-level selection `:279-283`.

Two shapes were proposed. B8's minimal version uses the variable that already exists:

```python
BY_CLASS = {
    "timeouterror": ErrorType.TIMEOUT,
    "connectionerror": ErrorType.DISCORD_CONNECTION_ERROR,
    "connectionreseterror": ErrorType.DISCORD_CONNECTION_ERROR,
    "clientconnectorerror": ErrorType.DISCORD_CONNECTION_ERROR,
}
if not error_str and error_class in BY_CLASS:
    return BY_CLASS[error_class]
```

B3's version uses `isinstance` and covers non-empty transport messages too:

```python
import httpx, asyncio
if isinstance(error, (asyncio.TimeoutError, httpx.TimeoutException)):
    return ErrorType.TIMEOUT
if isinstance(error, (httpx.TransportError, ConnectionError, OSError)):
    return ErrorType.SERVICE_UNAVAILABLE
```

**Decide the target enum for connection errors before writing the diff.** The two lanes disagree:
B3 maps transport failures to `SERVICE_UNAVAILABLE`, B8 maps them to `DISCORD_CONNECTION_ERROR`.
Both agree `TimeoutError` -> `TIMEOUT`. `SERVICE_UNAVAILABLE` is already in the retryable set at
`:268`; verify `DISCORD_CONNECTION_ERROR` is too before choosing it.

B3's `isinstance` version is preferable because it also catches
`httpx.ConnectError("[Errno 111] Connection refused")`, which has a non-empty string and so never
reaches B8's `if not error_str` guard.

- Making transport errors retryable means the bot will now actually retry them. Verify the retry
  ladder is bounded — see `DAB-042` (no whole-sequence deadline), which becomes slightly more
  reachable once these errors start retrying.
- `src/utils/error_manager.py` carries seven findings (`DAB-040`, `DAB-041`, `DAB-153`, `DAB-167`,
  `DAB-175`, `DAB-176`, plus this one). Land them as a short sequence of small commits rather than
  one rewrite, so each can be reverted independently.

  is already a transitive runtime dependency of `google-genai`, but it is not declared in
