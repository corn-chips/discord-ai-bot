## Context

Validation is a hand-maintained list of `if` statements. Nothing ties a new field to a new rule, so
coverage drifts. Whatever the YAML says is accepted verbatim and reaches the Gemini SDK, the rate
limiter or the message splitter as-is.

The scope of this ticket is the **six highest-blast-radius fields**, not all 43. The full pydantic
migration is the right long-term shape and is a separate, larger piece of work.

**The worked worst case — `DAB-112`.** `message_splitter.py:57-58`:

```python
56:        # Reserve space for continuation indicators only if enabled
57:        self.continuation_overhead = continuation_overhead if add_continuation_indicators else 0
58:        self.effective_max_length = max_length - self.continuation_overhead
```

With `split_length: 100` (the minimum validation permits) and `continuation_overhead: 100`
(unvalidated), `effective_max_length` becomes `0`. In `_find_optimal_split_points`,
`forced_split = min(current_pos + 0, len(content))` is `<= current_pos`, so the code falls to
`forced_split = min(current_pos + 1, ...)` and advances **one character at a time**:

```
   max_length= 2000 overhead=   50 effective=  1950 ->      10 parts in     10.3 ms  maxpart=2000
   max_length=  100 overhead=   50 effective=    50 ->     200 parts in     12.0 ms  maxpart=100
   max_length=  100 overhead=  100 effective=     0 ->  19,999 parts in    460.2 ms  maxpart=73
   max_length=  100 overhead=  150 effective=   -50 ->     200 parts in      8.5 ms  maxpart=100
```

19,999 sequential `channel.send` calls — an instant Discord rate-limit ban for the bot and a
destroyed channel. Note the pathological case is `effective == 0` **exactly**; both larger and
*negative* values happen to recover.

**Four fields were entirely dead** (parsed, never read) — `api_timeout_buffer`,
`edit_detection_max_output_tokens`, `system_prompt_thinking_addon` and
`progress_update_threshold`. **All four were deleted in `9894bcc`**, each at all three sites: the
`config.yaml` key, the `BotConfig` field in `src/config.py`, and the parser in
`src/config_helpers.py`. Nothing remains to delete or wire up, and the field total is now 96.
The most misleading of them, `system_prompt_thinking_addon`, took the substantial hand-written
`system_prompts.thinking_mode_addon` prompt block out of `config.yaml` with it; the three sibling
prompts under `system_prompts` are unaffected.

## Acceptance criteria

The six highest-blast-radius rules, in order:

- [ ] **`log_level`** — membership in `{DEBUG, INFO, WARNING, ERROR, CRITICAL}`. A typo silently
      becomes INFO today.
- [x] **The four `safety_*` enums** (DONE, round 2 Phase 2.4) (`safety_harassment`, `safety_hate_speech`,
      `safety_sexually_explicit`, `safety_dangerous_content`) — membership in the Gemini
      `HarmBlockThreshold` enum. This closes the silent fail-open where an unknown or mis-cased
      value degrades to `BLOCK_NONE` (`DAB-052`), including the SDK's own canonical names
      `BLOCK_ONLY_HIGH` and `OFF`, and any value with stray whitespace.
- [ ] **`split_length - continuation_overhead > 0`** — closes `DAB-112`. Add a
      `self.effective_max_length = max(1, max_length - self.continuation_overhead)` clamp in
      `MessageSplitter.__init__` **as well**; the service must not depend on config validation for
      its own invariant.
- [ ] **`pdf_render_scale`** — `0.1 <= pdf_render_scale <= 4.0`. Today `0`, `-2` and `20` all load.
- [ ] **`max_text_file_size_bytes`** — positive. Today `-1` is accepted and rejects every upload.
- [ ] **`extended_timeout >= response_timeout`**.

Plus:

- [x] The four dead fields are either deleted (all three sites each) or wired up. A dead multi-line
      prompt is worse than no prompt, because an operator will edit it expecting an effect.
      **Done in `9894bcc`** — all four deleted, all three sites each.
- [ ] `max_pdf_pages` is bounded — `1_000_000` is accepted today, disabling the one working PDF
      guard.

it is a separate, larger ticket.

## Risks and notes

- **Deleting a `BotConfig` field without its `config_helpers.py` parser entry breaks 3 tests** with
  `TypeError: BotConfig.__init__() got an unexpected keyword argument 'api_timeout_buffer'`
  (in `BotConfig.from_yaml`). That was caught during a verification run of the dead-code cleanup.
  The rule still applies to any future field removal: all three sites, together.
- `api_timeout_buffer` was `DAB-042`'s territory — it was the `+ 10` a previous fix deleted — but
  it was **deleted outright in `9894bcc`** before that ticket could claim it. `DAB-042` must now add
  a **new** key through all four places rather than wiring this one in.
- **Existing tests in the blast radius:**
  - `tests/test_config.py` as a whole asserts parsed defaults. Adding rules changes which configs
    load. (The four dead-field deletions already landed in `9894bcc` with the suite still green.)
  - `tests/test_bug_regressions.py:19-33`
    `test_long_fenced_line_is_lossless_and_within_discord_limit` constructs
    `MessageSplitter(max_length=2000, ..., continuation_overhead=50)` at `:21-26` — exactly the
    `effective_max_length` arithmetic the clamp changes.
  - `tests/test_discord_orchestration.py:234-239` builds `MessageSplitter(max_length=split_length,
    ..., add_continuation_indicators=False)` with `split_length` of 20 / 15 / 3. With
    `add_continuation_indicators=False`, `:57` forces `continuation_overhead = 0`, so the clamp is a
    no-op there — but `split_length=3` is exactly the degenerate regime.
  - `tests/test_discord_orchestration.py:296-318` asserts the exact chunking `["abc", "def", "gh"]`
    from `split_length=3` — a byte-level pin on splitter arithmetic.
- `MessageSplitter(max_length=0)` already raises `ValueError`; `max_length=1` is rejected by config
  validation but accepted by the service constructor and yields 2,399 parts for a 2,400-char string.
  The clamp should cover the constructor path too.
- Adding four new tunables in `DAB-198` (`pdf_conversion_timeout`, `max_render_pixels`,
  `max_pdf_size_bytes`, `max_image_size_bytes`) means four more four-place dances. Do this ticket
  first if both are in the same sprint, so there is a table to add them to.
