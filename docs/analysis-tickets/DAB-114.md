# DAB-114: Every LaTeX response with two or more equations fails to render

- Type: BUG
- Severity / Payoff: S2 (recalibrated; B6 filed S1). One keyword argument restores **100%** of
  multi-equation LaTeX rendering
- Effort: XS
- Priority score: 12.0 — impact Medium (2) x frequency Common (3) / effort XS (0.5)
- Confidence: **VERIFIED** — reproduced by two independent passes against the installed matplotlib
- Merged IDs: `B6-07`
- Blocks / Blocked by: **must ship with a `fig_height` bound** (`DAB-128`) — see Risks

## Context

`ContentRenderer._render_combined_latex_image` batches **all** expressions in a response into one
vertically-stacked PNG. Between each pair it draws a separator with
`ax.axhline(..., transform=ax.transAxes)`.

matplotlib rejects `transform=` on `axhline` outright — the guard is inside matplotlib, not the app.
The `if i < n - 1` condition means the call only executes when `n >= 2`, so **exactly one** equation
works and **every other case** throws, is swallowed, and falls through to the code-block fallback.

This is the normal case for a maths answer. The module's entire reason for existing is broken.

## Acceptance criteria

- [ ] `_render_combined_latex_image` returns PNG bytes (starting `b"\x89PNG"`) for 2, 3, 5 and 10
      expressions.
- [ ] A response containing two `$$...$$` blocks produces exactly one image attachment.
- [ ] The separator line still appears between stacked equations, in the right place.
- [ ] Single-expression rendering is unchanged.
- [ ] `fig_height` is bounded in the same change (see Risks) so that a 50-equation response cannot
      allocate an unbounded figure.

## Files to touch

- `src/services/content_renderer.py:489-493` — delete the `transform=` kwarg:

```python
ax.axhline(y=sep_y, xmin=0.02, xmax=0.98, color='#E0E0E0', linewidth=0.5)
```

`axhline`'s `y` is already in data coordinates and `xmin`/`xmax` are already axes-relative. Add
`ax.set_ylim(0, 1)` if the y positions need normalising, or replace the call with
`ax.add_line(matplotlib.lines.Line2D([0.02, 0.98], [sep_y, sep_y], transform=ax.transAxes, ...))`.

- `src/services/content_renderer.py:416-511` — bound `fig_height` (`DAB-128`).
- `src/services/content_renderer.py:504` — **optionally** narrow `except Exception` so a
  `ValueError`/`TypeError` from a bad API call is not silently degraded into "rendering
  unavailable". See Risks before doing this.

## Risks and notes

- **The two existing tests will keep passing, and that is the problem.** Repo-wide there are exactly
  two `plt.subplots` patch sites, both in `tests/test_content_renderer.py`, both inside
  `ContentRendererTest`:

  | Test | `def` at | patch at | call | argument |
  |---|---|---|---|---|
  | `test_image_renderer_closes_figure_after_success` | `:220` | `:248` | `:251` | `[("[1]", "x^2")]` — one expression |
  | `test_image_renderer_closes_figures_and_returns_none_on_error` | `:256` | `:284` | `:287` | `[("[1]", "x^2")]` — one expression |

  Two independent reasons the bug is invisible: `axis` is a `Mock`, which happily accepts
  `axhline(transform=...)`; and the input is a single expression, so line `:491` is never reached.
  Note `axis.transAxes = object()` at `:244` and `:280` — the mock deliberately supplies the very
  attribute whose use is the bug. Keep both tests (they are valid figure-lifecycle tests:
  `close_mock.assert_called_once_with(figure)` at `:254`, `close_mock.assert_called_once_with("all")`
  at `:290`) and **add** the unmocked one.

- **Narrowing the `except` at `:504` breaks
  `test_image_renderer_closes_figures_and_returns_none_on_error`.** That test sets
  `figure.savefig.side_effect = RuntimeError("render failed")` at `:281` and asserts `None` at
  `:289`. If the handler no longer catches `RuntimeError`, it propagates. Either leave the `except`
  broad in this ticket, or rewrite that test in the same commit.

- **`fig_height` is a latent DoS that this fix activates.** `DAB-128` (`B6-15`): `fig_height` is
  unbounded at `content_renderer.py:416-511` and "becomes a live DoS the moment `B6-07` is fixed",
  because today every multi-equation render dies before allocating the figure. Do not ship this
  alone.

- The wider renderer has five more open findings in the same file (`DAB-121` overlapping LaTeX
  spans, `DAB-122` currency eaten by `INLINE_LATEX_RE`, `DAB-123` `LATEX_UNICODE_MAP` prefix
  shadowing, `DAB-124` `SUBSCRIPT_MAP`, `DAB-125` not fence-aware). None blocks this one.
