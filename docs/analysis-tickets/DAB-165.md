## Context

`StructuredFormatter.format` splices extra field values **into** `record.msg` before calling
`super().format(record)`. `logging.Formatter.format` then calls `record.getMessage()`, which
performs `self.msg % self.args` whenever `record.args` is non-empty.

A stray `%` in an extra value therefore becomes a rogue conversion specifier in the format string.
`getMessage()` raises `TypeError`/`ValueError`, `Handler.handle` aborts, and `handleError` prints a
traceback **to stderr only**. The record never reaches the log file.

A `%` in the *message* alone is harmless. The formatter's mutation is what turns a benign extra into
a dropped record.

## Reproduction

```python
import logging, tempfile, os
from src.utils.logging_config import setup_logging
d = tempfile.mkdtemp(); lf = os.path.join(d, "bot.log")
setup_logging(log_level="INFO", log_file=lf, enable_console=False,
              enable_performance_logging=False)
logging.getLogger("t").info("indexed %s", 5, extra={"action": "50% done"})
logging.shutdown()
print(open(lf).read())     # the record is missing; a traceback went to stderr
```

## Acceptance criteria

- [ ] `StructuredFormatter.format` no longer mutates `record.msg`.
- [ ] The base message is formatted **first**, then extras are appended to the resulting string.
- [ ] A record whose extra value contains `%` appears in the log file.
- [ ] `format()` is idempotent — calling it twice on the same record yields the same string and
      leaves `record.msg` untouched.
- [ ] `include_extra_fields=False` means what it says (today the mutation happens regardless).
- [ ] Each extra appears exactly once in the output (today they are printed 2-4x per record —
      that is `DAB-164`, fixed by the same change).

## Files to touch

- `src/utils/logging_config.py` — `StructuredFormatter.format`, lines 42-101; the mutating line
  `:99`; the return `:101`.

The fix:

```python
def format(self, record: logging.LogRecord) -> str:
    base = super().format(record)
    if not self.include_extra_fields:
        return base
    extra_fields = [...]                      # unchanged collection logic
    return f"{base} [{', '.join(extra_fields)}]" if extra_fields else base
```

Optionally add a defensive `str(value).replace("%", "%%")` when building `extra_fields`.

class StructuredFormatterTest(unittest.TestCase):
    def test_percent_in_extra_value_does_not_drop_record(self):
        with tempfile.TemporaryDirectory() as d:
            lf = os.path.join(d, "bot.log")
            setup_logging(log_level="INFO", log_file=lf, enable_console=False,

    def test_format_is_idempotent_and_does_not_mutate_record(self):
        fmt = StructuredFormatter(include_extra_fields=True)
        rec = logging.LogRecord("t", logging.INFO, "p", 1, "msg", None, None)
        rec.user_id = 7
        first = fmt.format(rec)
        self.assertEqual(first, fmt.format(rec))     # idempotent
        self.assertEqual(rec.msg, "msg")             # record untouched
        self.assertEqual(first.count("user_id=7"), 1)

## Risks and notes

- **No existing test breaks** — `tests/test_logging_config.py` does not exist and there are zero
  references to `logging_config` across `tests/*.py`.
- **This is dormant on the shipped default.** `config.yaml` ships `file: null`, so only the console
  handler exists, and the console formatter is constructed with `include_extra_fields=False`. It
  activates the moment an operator enables file logging — i.e. exactly when they are trying to
  diagnose something.
- `setup_logging` is non-idempotent for the performance logger (handlers accumulate 1 -> 5) —
  that is `DAB-171` and lives in the same file. A test that calls `setup_logging` repeatedly will
  notice; use a fresh `TemporaryDirectory` per test and call `logging.shutdown()`.
- Changing the output shape means any log-scraping the operator has will see extras in the same
  place but only once. That is the intended correction.
