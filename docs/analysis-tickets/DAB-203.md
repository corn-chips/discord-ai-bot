# DAB-203: `test_command_registration.py` pins the degraded 22-command tree with byte-for-byte tuples and an absolute positional slice

**Status: LANDED** in round 2 Phase 5 — replaced by `EXPECTED_TOP_LEVEL_ORDER` and `EXPECTED_TOP_LEVEL_ORDER_WITH_IMAGES`, two full ordered lists. Note the honest verdict: this is de-brittling, not strengthening. No defect exists that the old slice misses and the lists catch, because `EXPECTED_SIGNATURE` is ordered and complete for the image-disabled tree; the win is a failure that names what moved, and 24 of 24 image-tree names pinned instead of 5.

- Type: BUG
- Severity / Payoff: S3 (promoted from S4 — "it is the reason a dead-code pass can silently delete
  `image_queue`")
- Effort: S — one test file, no production changes
- Priority score: 4.0 — impact Medium (2) x frequency Occasional (2) / effort S (1)
- Confidence: **VERIFIED** — prototyped, with four demonstrated pass/fail cases
- Merged IDs: `C2-19`; the de-brittling design is `I6-04`
- Blocks / Blocked by: **blocks `DAB-194`, `DAB-141`, `DAB-180`, `DAB-213`.** This is the single
  biggest unblocker in the backlog.

## Context

Two problems in one file.

**It pins the wrong tree.** The harness registers commands with `image_processing_service=None`,
which is the state a deployment reaches only when no nano-banana key is set *or* the image service
failed to start. A production bot with the key configured registers **24** top-level commands, not
22. Two live user-facing commands — `/edit-image` and `/image-queue` — are invisible to both
reference-counting and the suite.

**Its assertions carry no information.** They are so literal that every legitimate change breaks
them, the failure diff is a 2,600-character tuple dump, and the fix is always "paste the new list",
so reviewers stop reading it. Meanwhile it uses `callback.__name__`, coupling the test to function
names rather than behaviour.

**The `image_queue` consequence.** A repo-wide grep for `image_queue` returns **exactly one
reference — its own definition** at `src/bot/command_modules/general.py:264`. It is registered
conditionally under `general.py:124` (`if hasattr(bot, 'image_processing_service') and
bot.image_processing_service:`). So it is invisible to reference counting *and* to the test suite.
**Deleting `image_queue` removes a user-facing command and no test fails.** That is why this
blocks `DAB-194`.

`AGENTS.md` documents the contract as it stands, and will become stale guidance the moment this
lands:

> - `EXPECTED_SIGNATURE` (line 26) — ordered `(path, description, callback_name)` tuples; the
>   description must match the decorator byte-for-byte.
> - `len(bot.tree.get_commands()) == 22` (line 147) — bump only for a new *top-level* command or
>   group.
> - `len(EXPECTED_SIGNATURE) == 35` (line 148) — bump for any addition, subcommands included.
> - the positional slice guard at line 239, which breaks independently if anything is inserted
>   before index 10.

above it.

## Acceptance criteria

- [ ] Both surfaces are pinned: the degraded (22) and the healthy (24) trees. A comment at the
      current `:147` names which configuration `22` corresponds to.
- [ ] `EXPECTED_SIGNATURE`, `== 22`, `== 35` and the `[5:10]` slice are replaced by four layers,
      each with a distinct failure meaning:

  | Layer | Mechanism | Fails on | Tolerates |
  |---|---|---|---|
  | **WIRING** | `dict` subset: known path -> callback | rename, deletion, rewiring | additions |
  | **ORDER** | project the actual path list onto the known set, compare | reordering two existing commands | insertions anywhere |
  | **ADJACENCY** | `names[names.index("features")+1 : names.index("clear-cache")]` | conditional commands landing in the wrong neighbourhood | shifts of the whole block |
  | **STRUCTURE** | derived invariants: no duplicate paths, groups non-empty, Discord name regex, description non-empty and <= 100 chars, contract subset of tree | illegal or malformed trees | copy edits, additions |

- [ ] Descriptions are **validated** (non-empty, within Discord's 100-char limit) rather than
      **pinned**. A reworded description is a copy edit, not a regression.
- [ ] Adding a command mid-tree and rewording a description both pass.
- [ ] Swapping two registrars fails, with a diff containing only command names.
- [ ] Renaming or deleting a command fails, naming the exact casualty.
- [ ] `AGENTS.md`'s "Adding a slash command (three files, all required)" section is updated in the
      same change.

## Risks and notes

- **`ORDER` is the key idea and must be implemented correctly.** `relative_order(paths, known)`
  filters the live registration order down to commands already in the contract; comparing that
  against `list(REGISTRATION_CONTRACT)` protects the property `AGENTS.md` calls load-bearing while
  making insertion free. **Order is preserved; ordering is not frozen.**
- **A design mistake already made once during prototyping, do not repeat it:** the first draft of
  the STRUCTURE layer asserted *set equality* between the contract's top-level entries and the live
  tree. It failed case (d) — reintroducing exactly the brittleness the file exists to remove. It
  must be a **subset** assertion (`contract subset of tree`); deletion protection already lives in
  the WIRING layer's `missing` check.
- **Keep `test_public_command_helpers_remain_importable` (`:386`).** It pins the four re-exported
  helpers at `src/bot/commands.py:26` (`_format_report_status`, `_format_timedelta`,
  `_get_model_description`, `_truncate_text`), which the dead-code pass would otherwise delete.
- Four other tickets are waiting on this: `DAB-194` (the cleanup is dangerous without it),
  `DAB-141` (the description change and the checks assertion), `DAB-180` (refusing to register
  `/deepresearch` changes the tree), `DAB-213` (proving the cooldown decorators did not change the
  tree). Do it early in Sprint 2.
- This ticket changes only tests. It is the safest item in the backlog and the one with the largest
  downstream effect.
